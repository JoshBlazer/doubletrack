# M7 walkthrough: changes and their likely causes

**Exit check (ROADMAP):** Campfire's 22 `Vary` findings are 1 change naming Rails
`e38dd281d3`; shop's change names `json`; `accept c-…` accepts a whole change.

**Status: done.** CI [run 42110238868](https://github.com/JoshBlazer/doubletrack/actions/runs/42110238868), all 9 jobs ✓.
Design: [`docs/design/changes.md`](../design/changes.md); ADR 0031 (changes), ADR 0032
(local attribution).

## 1. Why

After M6 the Campfire report listed 22 findings that were one Rails change, and finding
the Rails commit behind it took a manual search. A reader's first two questions are "how
many distinct things changed?" and "which upgrade did it?".

## 2. What was built

* **Changes** (`Diff::Delta`, `Diff::Changes`). A change is the findings with the same
  channel, path, op and *delta*, whatever the route. The delta is token-level for
  strings: Campfire's three `Vary` values (`Accept` → `Accept, X-Requested-With`,
  `Accept, Sec-Fetch-Site` → `Accept, X-Requested-With, Sec-Fetch-Site`, …) all give
  `{"added": ["X-Requested-With"], "removed": []}`. Change ids (`c-…`) are stable.
* **Bundle changes.** Twins report their loaded gems in `hello` (with Bundler's git
  clone and revision for git sources, remote credentials removed). `run.json` gains
  `dependency_changes`: the gems whose version or revision differs.
* **Likely causes** (`Attribution`). Up to three distinctive words from each change are
  searched in those gems, offline: commits between the two revisions that add or remove
  the word (`git log -G` in Bundler's clone), new changelog lines, and source files that
  contain it on one side only.
* **Report and CLI** lead with changes. The overview lists each change with its routes,
  verified count and likely cause, plus the bundle changes. The findings page has one
  card per change; each finding page links to its change and shows the likely causes,
  where M6 had a "not available until layer L1" placeholder.
* **`doubletrack accept c-…`** accepts every finding of a change.
* **Eval:** `make eval` now fails if a change mixes findings of two planted differences.

Specs came first for the delta, changes, attribution (with a real temporary git
repository and gem directories), loaded gems and the report; the eval purity spec was
written in the same step as its implementation.

## 4. Limitations

* Grouping is by exact delta. A message that interpolates an id differs per route and
  stays separate changes.
* Causes are text matches. A change with no distinctive text (a status `200 → 500`) gets
  none, and the report says why. A common word can match an unrelated commit; the
  evidence and the matched word are shown.
* Commit evidence needs Bundler's git clone, so only git-sourced gems get commits.
  Released gems get changelog and source evidence.
* A gem the current bundle loads lazily (after boot) has no known old version, as with
  shop's `json`.
* On shop, 16 dependencies differ between Rails 8.0 and 8.1. Scanning their sources took
  10.4 s on the first run (cold file cache) and 1.6 s on the next. The search has a 60 s
  budget; changes past it say "not searched".
