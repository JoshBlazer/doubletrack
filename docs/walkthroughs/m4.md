## 3. What this shows, and what it doesn't

* **The proof is real, not asserted.** Every repro is checked twice:
  * in the run, on A, A′ and B;
  * by running the generated file under the app's bundle, on both Gemfiles (the
    integration spec on shop; the eval on all 13 planted findings).

  Both checks use the same lookup and comparison code (`Repro.lookup`,
  `Repro.reproduces?`).
* **Acceptance is narrow.** The baseline matches by fingerprint, so a *different*
  change at an enumerated leaf (for example, another status code) is a new finding.
  Same-shaped changes of free-form values are covered by an existing acceptance
  (ADR 0024).
* **Not shown:**
  * a repro that fails to reproduce in isolation. No finding in the fixtures needed the
    `not_reproduced` path. It's covered by unit specs (minimizer, writer), not by a real
    app.
  * RSpec auto-detection on a real app with `spec/`. It's unit-tested; the shop
    integration forces RSpec by rendering explicitly.
  * Postgres/MySQL. Snapshots are still SQLite only.
* **Limits:**
  * minimization is greedy, one pass, whole requests only;
  * the repro is not an idiomatic `rails_helper` request spec (ADR 0022);
  * the snapshot file must be copied along with the spec;
  * the app needs the gem in its test group.
