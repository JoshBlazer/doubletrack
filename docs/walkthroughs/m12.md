# M12 walkthrough: capture fidelity and scale

**Exit check (ROADMAP):** shop capture fidelity 100% including uploads; a parallel run
gives the same finding ids as a serial one.

**Status: done.** CI [run 42247996914](https://github.com/JoshBlazer/doubletrack/actions/runs/42247996914),
all 13 jobs ✓. Design: [`docs/design/scale.md`](../design/scale.md); ADRs 0039 (raw bodies,
uploads, hosts) and 0040 (parallel slots).

## 1. Raw bodies, uploads and hosts

* **Capture.**
  * A String `params` becomes `body`, or `body_base64` for non-UTF-8 bytes.
  * An uploaded file becomes `{"$upload": {"filename", "content_type", "data_base64"}}`. It
    is read from its path, or through `StringIO#string` when it has none, so the test's IO
    never moves. The limit is 5 MB per file.
  * The integration session's `host` and `https?` are recorded with each request; a full
    URL's host wins.
* **Replay.** Before each request the twin sets the session's host and HTTPS (or resets
  them to the defaults), sends `body` as the raw body, and turns `$upload` values back into
  `Rack::Test::UploadedFile`.
* **shop** gained:
  * a payments webhook that reads `request.raw_post`;
  * a receipt upload (`fixture_file_upload`);
  * an admin route constrained to `admin.example.com`, called with `host!` and with a full
    URL.

  Each has a test, and the tests pass on both Rails versions.
  `spec/integration/capture_spec.rb` checks that all of them are captured and that
  capture fidelity stays at 100%. The two host tests capture identically, so they are
  written once, as duplicates.

## 2. Parallel slots

`--parallel N` boots N slots of A, A′ and B, each with private databases (`<role>-<slot>`),
taking sessions from one queue. Slot 0 builds the snapshot templates, and every slot
restores from them. Fidelity is tallied in session order after replay, so it doesn't
depend on which slot ran what.

| Campfire, 242 sessions, seed 42 | `--parallel 1` | `--parallel 2` |
|---|---|---|
| replay | 79.5 s | **38.5 s** |
| boot | 11.3 s | 12.9 s (6 processes) |
| finding ids | 22 | **identical** |
| noise filtered / fidelity | 906 / 514 | 906 / 514 |

The machine is an i7-7600U (2 cores, 4 threads) under WSL2. On shop,
`spec/integration/run_spec.rb` checks that `--parallel 2` gives the same finding ids and the
same A/A′ noise as one slot.

## 3. Limitations

* Uploads are embedded in sessions files as base64, at most 5 MB each.
* Rack env other than headers, the host and HTTPS is still not captured.
* Each slot is 3 app processes, so memory grows with N. The default stays 1.
* PostgreSQL restores (about 2 s per session, M10) run in parallel across slots; preparing
  copies ahead of time is not built.
