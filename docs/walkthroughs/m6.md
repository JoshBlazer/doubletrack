# M6 walkthrough: a real open-source app (once-campfire)

**Exit check (ROADMAP):** published report URL + walkthrough + any upstream issues filed.

**Status: in progress.** The run and this walkthrough are done locally. Publishing the
report and contacting the maintainers (RISKS R9) wait for the maintainer's go-ahead,
one step at a time.

## 1. The app and the upgrade

* **App:** [basecamp/once-campfire](https://github.com/basecamp/once-campfire), MIT
  licence, SQLite, Minitest with about 650 tests, 154 routes.
* **Upgrade:** [PR #423](https://github.com/basecamp/once-campfire/pull/423), "Update
  Rails to main at 8b06b0eb", merged 2026-11-04. It changes only `Gemfile.lock`:
  * Rails main `e3d5c569` → `8b06b0eb` (1,049 commits, including the 2026-11-04 security
    release, merged into main by `6782df4a`);
  * rack 3.2.7 → 3.2.8, addressable 2.9.0 → 2.9.2, actionview's new
    `rails-html-sanitizer >= 1.7.2` floor.

  The application code is identical on both sides, which is the situation Doubletrack
  is built for. The PR also makes testable claims: the bump "breaks nothing", the new
  `message_serializer = :json` default is harmless, and the `Forwarded` /
  `X-Forwarded-For` spoofing check doesn't reach Campfire.
* **Why not the earlier upgrade** (`9d75c8b7e`, Rails main `1a02651` → `e3d5c569`, with
  app changes): at `1a02651`, with Minitest 6.0.6, `bin/rails test` loads no test files.
  Minitest 6 made plugin loading opt-in and that Rails revision doesn't load its own
  plugin (later Rails main calls `Minitest.load :rails`). There was nothing to capture.

## 2. Setup (no change to Campfire's code)

```sh
git clone https://github.com/basecamp/once-campfire.git
git -C once-campfire worktree add ../pr423 86dd525e1~1     # main just before the PR
cd pr423
cp Gemfile Gemfile.next                                     # same Gemfile...
git -C ../once-campfire show 86dd525e1:Gemfile.lock > Gemfile.next.lock   # ...the PR's lockfile
bundle install && BUNDLE_GEMFILE=Gemfile.next bundle install
# system packages Campfire's CI installs: libvips (loaded at boot), ffmpeg
```

Then, from the Doubletrack repository:

```sh
bundle exec exe/doubletrack capture ~/m6/pr423
bundle exec exe/doubletrack run ~/m6/pr423
```

## 3. What Doubletrack got wrong first, and the fixes

Campfire was the first app Doubletrack hadn't been written against. Each problem was
fixed in Doubletrack with a failing spec first:

| Symptom on Campfire | Cause | Fix |
|---|---|---|
| `run` would stop with "dual boot not effective" | both sides report `Rails.version` `8.2.0.alpha` | twins report the git revision; labels read `8.2.0.alpha (e3d5c569d2)` (`d9de98c`) |
| `capture`: boot error shown without its message | only the last 30 lines of output were shown | keep the exception line above a backtrace (`f4a7fcd`) |
| `capture`: 649 tests ran, 0 requests captured | the lockfile says `BUNDLED WITH 4.0.13`; Bundler re-executes the test process and drops `-r<probe>` | probe in `RUBYOPT`; twin pipes stay inheritable until the bundle loads (ADR 0028, `166fca5`) |
| 25 of 48 findings were `no such table: bans` on a random twin | Campfire's WAL-checkpoint thread holds its own connection; restore deleted and copied the file under it | restore through SQLite's backup API (ADR 0029, `166fca5`) |
| generated Minitest names like `…_alpha__e3d5c569d2__behavior` | parentheses in the new label | collapse runs (`8c76d8f`) |
| on Ruby 4.0.9, 15 data-changing findings that didn't reproduce: a `DELETE push_subscriptions` in a sign-in request | Campfire's web-push pool finished an earlier session's work while a later request was recorded; the recorder took writes from any thread | side effects from other threads go to `background`, never diffed (ADR 0030, `b2ad604`) |
| with seed 7, a gzip page body differed on B and didn't reproduce | `Zlib.gzip` stamps the header with C-level `time()`, which the frozen clock doesn't reach | compare gzip bodies by decoded content (`9ce0fc2`) |

CI for the first three rows: [run 42046719066](https://github.com/JoshBlazer/doubletrack/actions/runs/42046719066), all 9 jobs ✓. CI for the rest: [run 42082544994](https://github.com/JoshBlazer/doubletrack/actions/runs/42082544994), all 9 jobs ✓.

## 4. Results

Final run: `20261105T180436Z-42`, on Campfire's own Ruby (4.0.9, as its
`.ruby-version` says), WSL2, i7-7600U.

```console
$ bundle exec exe/doubletrack capture ~/m6/pr423
Captured 215 sessions (553 requests) from 285 tests that made requests
  tests: passed
  duplicates written once: 44
$ bundle exec exe/doubletrack run ~/m6/pr423 --seed 42
Doubletrack 20261105T180436Z-42: Campfire, Rails 8.2.0.alpha (e3d5c569d2) → 8.2.0.alpha (8b06b0eb98)
  215 sessions, 553 requests replayed on control A, control A′ and candidate B
  Findings: 22 new  (data-changing 0, user-visible 0, cosmetic 22)
  Reproductions: 22 verified, 0 not verified (minitest, .../repro/test/doubletrack)
  Capture fidelity: 502/553 requests replayed with the status their test saw
  Noise filtered: 880 (880 A/A′ differences observed)
  Route coverage: 68 of 154 routes (44%)
  Verdict: Ready to ship
```

Timings: boot 4.7 s (three twins in parallel), snapshot 1.1 s, replay 71.7 s, analysis
28.3 s, reproductions 4.5 s, report 0.8 s.

**Stable across seeds.** Seeds 42, 7 and 1234 give the same 22 finding ids (identical
sorted id lists).

**The finding: every negotiated response now varies on `X-Requested-With`.** All 22
findings are one change, seen on 22 routes, 131 occurrences in 72 sessions:

| Control A (`e3d5c569`) | Candidate B (`8b06b0eb`) | Occurrences |
|---|---|---|
| `Vary: Accept, Sec-Fetch-Site` | `Vary: Accept, X-Requested-With, Sec-Fetch-Site` | 41 |
| `Vary: Accept, Accept-Encoding, Sec-Fetch-Site` | `Vary: Accept, X-Requested-With, Accept-Encoding, Sec-Fetch-Site` | 40 |
| `Vary: Accept` | `Vary: Accept, X-Requested-With` | 1 |

Cause: Rails [`e38dd281d3`](https://github.com/rails/rails/commit/e38dd281d340d28bda39877ee83665f092091de2),
"Vary rendered responses by negotiation headers" (GHSA-r9jg-fmfx-2gv6), part of the
2026-11-04 security release. Responses now vary on `Accept` and `X-Requested-With`
whenever the format isn't in the URL, and the fields are appended to an existing `Vary`.
Browsers are unaffected. A shared cache in front of Campfire now keys its pages on one
more request header, which is the point of the fix. PR #423 lists three of the
release's advisories as reaching Campfire. This one isn't among them, though Campfire
also caches complete pages itself (`CachedResponses`). Its own tests pass on both
sides.

**Each reproduction runs against Campfire itself.** With
`gem "doubletrack", path: ...` added to a local copy of the Gemfile (reverted
afterwards), all 22 generated Minitest files pass on `Gemfile` and fail on
`Gemfile.next` (`specs=22 pass_on_current=22 fail_on_next=22`). One failure reads:

```
--- expected
+++ actual
-"Accept, Accept-Encoding, Sec-Fetch-Site"
+"Accept, X-Requested-With, Accept-Encoding, Sec-Fetch-Site"
1 runs, 1 assertions, 1 failures, 0 errors, 0 skips
```

**What the PR claimed, checked.** "Breaks nothing": no data-changing or user-visible
difference on the 553 replayed requests. The `message_serializer = :json` default and
the `Forwarded`/`X-Forwarded-For` check produced no difference in the replayed traffic.
Captured tests send neither header, so the spoofing check is not exercised here.

**Noise** (880 A/A′ differences, masked per route and listed on the noise page): session
tokens in cookies (58 paths), cache keys that embed tokens (30), bcrypt digests and
API/join tokens in SQL binds, and parts of the HTML of 10 routes.

**The path there.** Before the fixes in section 3, the same upgrade produced 48
findings (25 from the snapshot race, 1 from the push pool) on Ruby 3.4.12, then 37 on
Ruby 4.0.9 (15 from the push pool), then 23 with seed 7 (1 from gzip timestamps). Each
false finding was caught because its reproduction didn't verify, then explained and
fixed in Doubletrack, not suppressed.

## 5. Limitations seen on this app

* **Not replayable, skipped and reported by capture:** 23 bot-API tests that send a raw
  string body, and 3 file uploads (`Rack::Test::UploadedFile`).
* **Capture fidelity 91%:** the mismatches are requests whose outcome depended on state
  built inside the test (records created in `setup`, signed Active Storage URLs that
  have expired by replay time, mocha stubs). The coverage page lists each one.
* **Background threads:** Campfire's web-push pool and WAL-checkpoint thread run during
  replay. Their side effects are recorded under `background` and not diffed (ADR 0030),
  so a Rails change inside work the app pushes to its own threads isn't reported.
* **Five sessions named `integration-session-NNN`:** one test signs up five users at
  once, each through its own integration session in a thread; the probe's test name is
  per thread. Each stays its own session (separate cookies), but unnamed.
* **Route coverage 44%:** Action Cable, system tests and the bot API aren't replayed.
