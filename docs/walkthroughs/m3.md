Timings for that run: boot 3.2 s (three twins in parallel), snapshot 1.0 s, replay

**The one finding is a real upgrade difference.** In session `unstubbed-rate`, the rates
API call is blocked, and the app parses the empty body:
* on 8.0 it raises `JSON::ParserError: unexpected token at ''`;
* on 8.1 it raises `unexpected end of input at line 1 column 1`.

The 8.1 bundle pins `json 3.1.0`, while the 8.0 bundle uses Ruby's default `json` 2.x.
Any app that shows parser messages to users, or matches on them, would see this change.
It's user-visible and not data-changing, which matches the rules.

The 13 findings on `changes` cluster across sessions. For example, `jobs[*].queue_name
changed` appears in 2 sessions and is reported once. In both apps, the 2 noise values
filtered are the planted `SecureRandom` `request_token` in `GET /orders/:id.json`: A and
A′ disagree on it, so it's masked. The irrelevant HTML change in `changes` (attribute
order and whitespace in the index) produced no finding.

### The jobs decision, measured (ADR 0014)

The same `changes` app with `--no-perform-jobs` gives 10 findings instead of 13. Plant
P3 is **missed**: the confirmation email's new subject is only visible when the job
runs. With jobs performed inline (the default), recall is 9/9. Without them it would be
8/9.

## 3. What this shows, and what it doesn't

* **The three-way comparison works on real differences.** On shop it found a real Rails
  8.1 behavior change, with zero noise.
* **The noise canceller is necessary.** Without control A′, the planted `request_token`
  would have been reported as a user-visible finding in both apps.
* **One cause gives one finding,** within a route. A framework change that affects every
  JSON endpoint still gives one finding per route (ADR 0019).
* **The report** is static: offline, works without JS, axe-clean on 5 pages in CI. I
  checked it as rendered text and with axe. I did not review it visually in a browser.
* **Limits of the eval:**
  * One planted app with 9 plants is a small corpus. Each plant is app code branching on
    the Rails version, not a real Rails change.
  * Precision 1.00 here means no false positives *on this corpus*. It isn't a general
    claim.
  * Array diffs are index-based. An extra SQL write early in a request shifts later
    paths and can produce several findings.
* **Not built (later milestones):** reproduction specs and `accept` (M4; the report
  shows them as "arrives in M4"), traffic capture from tests (M5), and bisect (L1).
