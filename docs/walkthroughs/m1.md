# M1 walkthrough: side-effect recorder

> A record of the project at the end of this milestone. Later milestones changed some
> details; the README, `docs/ARCHITECTURE.md` and `docs/formats/` describe the current code.

**Exit check:** an integration test asserts that a trace for a known request contains
the expected side effects.

**Result: done (2026-11-03).** `spec/integration/recorder_spec.rb` passes on **both**
twins (Rails 8.0.5.1 and 8.1.4), locally and in CI [run 41556339580](https://github.com/JoshBlazer/doubletrack/actions/runs/41556339580): all jobs green, and the
integration job ran all 12 recorder examples (`15 examples, 0 failures` with the M0 ones).

Design: [`docs/design/recorder.md`](../design/recorder.md). Format:
[`docs/formats/trace.md`](../formats/trace.md). Decisions: ADR 0011 (memory cache, cleared
per session), ADR 0012 (`Net::HTTP` interceptor), ADR 0013 (protocol schema_version 2).
Machine: same as M0 (WSL2, i7-7600U, Ruby 3.4.12).

## 1. Order of work

1. Design note and trace format written first.
2. `spec/integration/recorder_spec.rb` written next and **run red**:
   `12 examples, 12 failures` (twins didn't return traces yet).
3. Implementation: `lib/doubletrack/recorder/{recorder,http_interceptor,jsonable}.rb`,
   worker changes, and an overlay with `:memory_store` and `show_exceptions = :rescuable`.
4. First green run of the exit check: 13/15. The 2 failures were **a bug in the spec**:
   the rates stub used a prefix match, so it also answered the GBP lookup that was meant
   to be blocked. The stub now matches the exact EUR URL.
5. Unit specs for the interceptor and the value converter. The converter's property test
   **found a real bug**: binary *hash keys* passed through unconverted and broke
   `JSON.generate`. Fixed, with a dedicated regression example.
6. First CI run (41556048656): integration green, but unit specs failed on Ruby 3.2/3.3.
   `Time#iso8601` is core only from Ruby 3.4 (needs `require "time"` before), and I only
   had 3.4 locally. While fixing it I found a worse bug: the converter called
   `Time#utc`, which converts **in place**, so recording a trace could mutate the app's
   own `Time` objects. Now it uses `getutc`, with a regression spec that failed before the
   fix (`expected: 3600, got: 0`).

## 4. What this shows, and what it doesn't

* **The sandbox holds.** The GBP lookup had no stub, so the interceptor returned the
  synthetic `503 x-doubletrack: blocked`, no socket was opened (unit spec asserts
  `TCPSocket.open` is never called), and the app's resulting `JSON::ParserError` became
  data in the trace instead of failing the session.
* **`after_commit` is observed.** `OrderConfirmationJob` is enqueued from
  `after_create_commit` and shows up, because nothing is wrapped in a rolled-back
  transaction (ADR 0004).
* **Noise is visible, on purpose.** Wall-clock `created_at`/`updated_at`, `x-request-id`,
  `x-runtime`, and an `etag` derived from a body with timestamps. Time freezing (M2) and
  the three-way noise mask (M3) handle these; the recorder keeps raw evidence.
* **Not covered:** jobs are recorded but not performed, so mail sent *by jobs* isn't
  observed (only `deliver_now` in the request). HTTP clients that bypass `Net::HTTP`
  aren't intercepted (RISKS R6). The database isn't reset between sessions until M2.
